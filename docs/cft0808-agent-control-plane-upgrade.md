# 三省六部这次要大改：不是再做一个更漂亮的 OpenCode

2026 年 6 月 1 日，NVIDIA 和 Microsoft 把个人电脑重新放到了 AI agent 的语境里。

我看到这个消息时，第一反应不是“又来了一个 AI PC 概念”。

我更在意的是另一件事：

如果 PC 真的从“人操作工具”变成“Agent 代你完成一组工作”，那现在这些 Agent 工具最大的问题，可能不是模型不够聪明，而是缺一套能让它可靠工作的制度。

OpenCode、OpenClaw、Codex 这一类工具已经证明了一件事：

模型可以读文件，可以改代码，可以打开网页，可以跑命令，可以处理本地文档，也可以把结果写回工作区。

这件事当然重要。

但这还不是终点。

真正的问题是：当一个 Agent 能动你电脑里的文件、网页、命令、PPT、PDF、代码仓库时，我们到底用什么结构来约束它、观察它、复盘它、积累它？

这就是我这次想大幅升级三省六部的原因。

## 01｜我不是要做一个科研探索平台

前段时间我一直在想三省六部的定位。

它可以做科研，也可以做内容，也可以做代码，也可以做日常办公。

但如果我把它说成“科研探索平台”，这个定位反而窄了。

我真正想做的，不是一个垂直工具。

我想做的是 OpenCode / OpenClaw 的升级版。

更准确地说，是一个 Agent Control Plane。

OpenCode 更像一个强大的执行终端。它让模型可以在代码工作区里行动。

OpenClaw 更像一个多 Agent 协作框架。它强调角色、能力和协作。

三省六部要补的不是“再加一个聊天框”，也不是“把界面做得古风一点”。

它要补的是控制层。

也就是：

- 用户怎么下达一个足够清楚的目标；
- 系统怎么把目标变成可执行的 RunSpec；
- 任务需要哪些能力，哪些能力不能乱用；
- 哪些动作可以自动执行，哪些必须先审议；
- 每一步到底是谁做的，用了什么工具，产生了什么文件；
- 最后这些经验怎么沉淀成下一次可复用的能力。

如果没有这一层，Agent 越强，系统反而越不稳。

## 02｜单纯多 Agent 编排还不够

多 Agent 编排有价值。

一个 Agent 负责规划，一个 Agent 负责执行，一个 Agent 负责审查，听起来很合理。

但这里有一个问题：

如果这些 Agent 只是流水线上的几个节点，那它本质上还是一个自动化流程。

它可以加速。

但它未必更可靠。

我以前写过一句话：单 Agent 没有反对自己的机制。

现在我觉得还可以再补一句：

多 Agent 如果没有制度，也只是多个 Agent 一起把错误执行得更快。

所以三省六部的价值，不在于“有多少个角色”，而在于它天然把一件事拆成了几类权力：

- 太子：接收目标，判断这是不是一个真正的任务；
- 中书省：把模糊目标整理成方案；
- 门下省：审议边界、风险和缺口；
- 尚书省：把方案变成可执行调度；
- 六部：按能力执行具体工作；
- 刑部：校验结果是否可信；
- 史馆：把过程、产物、经验沉淀下来。

这不是古风包装。

这是一个治理模板。

## 03｜Agent Runtime 和 Agent Control Plane 要分开

我现在越来越确定，未来这类系统要分两层。

第一层是 Agent Runtime。

它负责真正干活：

- 读写文件；
- 执行命令；
- 操作浏览器；
- 修改代码；
- 处理办公文档；
- 调用模型和工具；
- 在沙箱或工作区里完成动作。

OpenCode、OpenClaw、Codex、Browser、Documents、Spreadsheets 都可以看作 runtime 或 capability executor。

第二层是 Agent Control Plane。

它不直接替代 runtime。

它负责决定：

- 这个任务该不该执行；
- 应该调用哪些能力；
- 应该交给哪个 runtime；
- 风险等级是多少；
- 是否需要先审议；
- 执行过程怎么展示；
- 产物怎么归档；
- 失败后如何重试、回滚或升级。

很多平台的问题，就出在把这两层混在一起了。

用户只看到一个聊天框，背后到底发生了什么很难判断。

模型执行得顺的时候，看起来很神奇。

一旦卡住，就不知道是模型没理解、工具没接上、任务没派发、命令失败，还是输出已经生成但用户找不到。

这就是我现在要修的地方。

## 04｜三省六部这次要升级的不是外观，而是任务制度

这次改造，我会把三省六部从“固定流程看板”升级为“可配置的 Agent 运行控制台”。

核心会围绕几个对象展开：

| 对象 | 作用 |
|---|---|
| Goal | 用户真正想完成什么 |
| RunSpec | 目标被整理后的可执行规格 |
| Capability | 系统能调用什么能力 |
| RuntimeAdapter | OpenCode、OpenClaw、Codex 等执行适配器 |
| Policy | 哪些能力可以自动用，哪些必须审批 |
| RunGraph | 任务执行图，而不是一条死流程 |
| RunEvent | 每一步真实发生了什么 |
| Artifact | 最终文件、报告、截图、补丁和链接 |
| Memory | 可复用的经验、偏好和工作流 |

这里最重要的是 RunSpec。

过去用户下达一句话，系统就把它塞进任务看板。

这当然能跑。

但它不够清楚。

新的入口应该先把一句话变成结构化信息：

- 目标是什么；
- 运行方式是只出方案、直接执行，还是边做边问；
- 需要代码、文件、命令、浏览器、文档中的哪些能力；
- 风险是低、中、高；
- 应该走哪条治理链路；
- 产物应该沉淀到哪里。

这样任务不是“丢给模型试试看”，而是先进入一个可观察、可追溯、可审议的运行规格。

## 05｜为什么这对未来 AI PC 很关键

如果 AI PC 只是让用户更快打开应用，那它没有真正改变 PC。

真正的变化是：用户不再逐步点按钮，而是把一段工作交给 Agent。

例如：

- 检查这个仓库为什么构建失败，并修复；
- 打开某个网页，提取关键资料，整理成表格；
- 读取一个 PPT，重写结构，并导出新版本；
- 看一下我这周的输出，写一篇公众号文章；
- 把某个任务完成后的文件、截图、日志全部归档。

这些任务都不是单纯问答。

它们涉及电脑资源。

一旦涉及电脑资源，就必须有控制层。

否则用户会遇到几个很现实的问题：

- Agent 到底有没有开始执行；
- 卡住时卡在哪里；
- 它为什么调用这个工具；
- 它改了哪些文件；
- 它生成的文件在哪里；
- 它有没有把同一条信息重复展示好几遍；
- 它的失败能不能重试；
- 它做过的事能不能沉淀成下一次的能力。

这也是我为什么不满足于 OpenCode 原来的终端式交互。

终端对程序员友好。

但如果 Agent 要成为普通工作流的一部分，它需要一个真正的任务入口和可观察界面。

## 06｜第一步我已经开始改

这次第一版改造，我先做三件事。

第一，新增统一的“下达指令”入口。

用户不用先理解太子、中书、门下、尚书分别怎么点。

用户只需要写清楚目标，选择运行方式，系统会把它整理成 RunSpec，再进入现有三省六部链路。

第二，新增能力注册表。

能力不再是写死在某个页面里的按钮，而是被明确登记：

- OpenCode Runtime；
- OpenClaw Runtime；
- 代码工作区；
- 本地文件；
- 命令执行；
- 浏览器；
- 办公文档；
- 任务产物；
- 规划与审议。

这一步很基础，但很重要。

因为以后平台能不能扩展，就取决于能力是不是一等对象。

第三，新增 RunSpec 预览。

用户在下达任务前，可以看到系统初步判断：

- 这个任务会调用哪些能力；
- 风险等级是什么；
- 目标部门是谁；
- 会经过哪些治理节点。

这不是为了增加复杂度。

恰恰相反，是为了减少混乱。

以前很多卡顿，本质上是系统内部发生了事，但用户看不到。

现在要把关键状态提前展示出来。

## 07｜后面真正难的是 Policy 和 RunGraph

当前版本只是第一步。

后面更重要的是两件事。

第一是 Policy。

不是所有能力都应该自动放开。

读文件、写文件、执行命令、打开网页、发消息、删除文件、访问外部服务，它们的风险不是一个级别。

未来三省六部应该支持：

- 只读模式；
- 沙箱模式；
- 高风险命令审批；
- 文件写入前 diff 审批；
- 外部网络访问记录；
- 隐私和密钥保护；
- 失败后的回滚策略。

第二是 RunGraph。

现在的三省六部还是偏固定流程。

但真实任务不是每次都走同一条线。

有些任务只需要计划。

有些任务需要代码执行。

有些任务需要浏览器验证。

有些任务需要先读文件，再生成 PPT，再导出 PDF。

所以未来不能只看状态列。

要看任务图。

一个节点代表一次计划、一次工具调用、一次审批、一次文件生成、一次测试、一次校验。

这时平台才真的从“看板”变成“Agent 运行控制台”。

## 08｜我对三省六部的新定义

以前我会说：

edict 是一个多 Agent 编排框架。

现在我想改一下。

edict 是一个面向个人电脑和工作流的 Agent Control Plane。

它利用三省六部制的优点，把 Agent 的目标、能力、权限、执行、审议、产物和记忆组织起来。

它不追求把所有模型都包起来。

它追求的是让模型在真实电脑里工作时，不失控、不混乱、不丢产物、不假装自己做了事。

这件事听起来没有“重新定义 PC”那么大。

但我觉得它更接近我能做、也更值得做的部分。

模型会继续变强。

本地算力也会继续增强。

OpenCode、OpenClaw、Codex 这类 runtime 会越来越多。

但越是这样，越需要一个控制层来回答一个朴素的问题：

当 Agent 真的开始替你操作电脑时，你凭什么相信它？

三省六部这次大改，就是从这个问题开始。

工程很重要。

但工程不是终点。

制度，才是 Agent 真正进入个人电脑之后绕不开的东西。
